## 发现并修复的问题（3 个，全部为"只在打包环境出现"）

### 1. 资源相对引用被路由前缀污染（白屏根因）

- 现象：打包 app 启动后白屏，console 报 module script MIME 错误（fallback 返回 HTML）
- 根因：electron-vite 在 production **无条件强制** renderer `base: "./"`（源码 lib 块 512 行），
  产物 index.html 以 `./assets/...` 相对引用；深链加载（`app://bundle/auth/login`）时
  相对引用被解析为 `/auth/assets/...`，磁盘不存在 → 协议处理器 SPA fallback 返回 HTML
- 修复（双层）：
  - `src/main/index.ts`：app:// 协议处理器对被路由前缀污染的资源路径重写
    （`/auth/assets/...` → `/assets/...`，覆盖 assets 与 yuque-assets 两类）
  - `build/shared.ts` 加 `base: "/"`（对 Web 端 build 生效；桌面端被 electron-vite
    覆盖，由上一条协议层兜底）

### 2. 后端 CORS 白名单缺少 app:// 协议 origin

- 现象：登录请求发出（desktop 桥接直指 `http://localhost:3200/api`）但登录态不生效
- 根因：`app://bundle` origin 不在后端 CORS 白名单（只有 null 与 localhost 正则），
  跨域响应被浏览器拦截，token 无法持久化
- 修复：`xiaoye-server/src/main.ts` 默认白名单加入 `app://bundle`
  （对应 xiaoye-server commit）

### 3. node_modules 全量打入安装包（约 200MB 冗余）

- 根因：electron-builder 默认把 package.json dependencies 的 node_modules 打进包；
  本项目 renderer 依赖已在构建期打包进 bundle、主进程零第三方运行时依赖
- 修复：`electron-builder.yml` files 增加 `!node_modules/**` 显式排除

## 已知限制（记录，不阻塞）

- **未签名**：本机无 Developer ID 证书，产物未做 macOS 代码签名。本机运行正常；
  分发给他人时 Gatekeeper 会拦截（右键打开或后续接入签名+公证）
- **API 地址固定 localhost:3200**：桌面桥接下发的 serverBaseUrl 来自主进程配置，
  当前指向本机后端；对外分发需配云端后端地址（产品化前的配置项）
- electron-vite 强制 base 的行为已用协议层重写绕过；若未来 electron-vite 支持自定义
  base，可去掉重写逻辑
