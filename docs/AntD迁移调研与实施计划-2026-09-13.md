# Ant Design Vue 迁移调研与实施计划（2026-09-13）

> **⚠️ 本计划已废弃，仅作选型对照保留。** 2026-09-13 选型决策：组件库采用 **Element Plus**（理由见 [ElementPlus调研与选型对比-2026-09-13.md](./ElementPlus调研与选型对比-2026-09-13.md)），正式执行以 [ElementPlus迁移实施计划-2026-09-13.md](./ElementPlus迁移实施计划-2026-09-13.md) 为准。

> **For agentic workers:** 执行本计划请配合 superpowers:subagent-driven-development（推荐，每任务派发独立 subagent）或 superpowers:executing-plans（本会话内顺序执行）。步骤用 checkbox（`- [ ]`）跟踪，每个任务以一次 commit 收尾，全部改动只在 `xiaoye/` 仓库。

**Goal:** 把前端自建 App* 组件族的「交互复杂度」部分换底到 ant-design-vue，同时保持语雀 1:1 视觉不回退、对外 API 不变、每阶段可独立交付可回滚。

**Architecture:** 视图层继续只依赖自建 App* 组件（调用方零改动）；适配层内部换成 antd 组件；antd 的视觉由 ConfigProvider 桥接 `--kb-*` 语雀 token 驱动；用 `prefixCls="kb-ant"` 与 Lake 编辑器注入的 antd v4 静态 CSS 做**类名隔离**；Tailwind 4 继续负责布局与页面级样式。

**Tech Stack:** ant-design-vue 4.2.6（精确锁版）+ Vue 3.5 + Tailwind CSS 4（CSS-first @theme）+ unplugin-vue-components（自动注册 + AntDesignVueResolver）+ Vitest。

## 一、调研结论（先读这个）

### 1.1 三个必须知道的硬事实

**事实 1：ant-design-vue 已停止积极维护。**
官方在 GitHub issue（#7659）宣布：自 Ant Design React 6.x 发布后，ant-design-vue 进入维护模式，**不会有 5.x**。npm 最新版即 4.2.6（2026-09 经 npm registry 核实），peer 依赖 `vue >= 3.2.0`，与本项目 Vue 3.5.25 兼容。2025-01 起只修重大 bug 与安全问题。

→ **对策**（本计划因此定型为三条）：① 精确锁版 `4.2.6`（不用 `^`）；② **所有页面经自建 App* 适配层使用 antd**，antd 可整体换底而不动业务代码；③ 收敛使用的组件面（只用成熟核心组件，不用冷门组件）。

**事实 2：Lake 编辑器注入的 antd v4 静态 CSS 与 ant-design-vue 类名正面冲突。**
`yuque-editor-core` 随包带完整 antd v4.24.13 静态 CSS（26,885 行、7,126 个 `.ant-*` 选择器，含 body/h1/button/input 全局 reset），由 `yuqueAssets()` vite 插件以 `/yuque-assets/antd.css` 提供、编辑器运行时**动态注入且 unlayered**。ant-design-vue 同样渲染 `.ant-*` 类名——两套 `.ant-*` 共存会互相污染（编辑器旧静态样式盖掉 antd-vue 的 CSS-in-JS 主题，或反之）。

→ **对策**：主方案用 ConfigProvider `prefixCls="kb-ant"` 把 antd-vue 全部类名改前缀（我方改前缀，不动 2.7 万行编辑器资产）；Phase 1 设 spike 验证，失败则启用附录 A 的作用域化 fallback。

**事实 3：项目目标是语雀 1:1 复刻，antd 默认视觉 ≠ 语雀。**
已有的三层 token（`tokens.css`，色值移植自语雀 v4.2.1，明暗双套）是视觉唯一事实源。

→ **对策**：antd 只承担**交互复杂度**（焦点陷阱、键盘导航、浮层定位、滚动态），视觉一律由 token 桥接 + 适配层 scoped CSS 校准；每组件迁移后跑截图对比，不达标就修 token 映射，不硬迁。

### 1.2 总结论

**可行，但建议「选择性迁移」而不是全量替换。** 迁移收益集中在 antd 比自建强的地方（对话框栈/焦点管理、下拉键盘导航、表单控件成熟度）；纯视觉组件（按钮、徽标、toast、卡片）自建实现已经完整且深度 token 化，换成 antd 反而要重写 antd 的大部分样式（cssinjs unlayered 会压过 Tailwind @layer，见 AGENTS.md 坑 6），属于负收益。计划按「可中断」设计：做完 Phase 1-2（基建 + 表单控件）即可停住评估，不必一次到底。

### 2.2 与迁移相关的现状事实

- `build/shared.ts:52-57`：`unplugin-vue-components` 已配置（dirs 绝对路径 + dts），**尚未配 resolver**。
- `main.ts` / `App.vue`：无任何全局 Provider 挂载点；`App.vue` 模板只有 `<RouterView />`。

- 依赖现状：`@floating-ui/dom`、`@vueuse/core`、`tailwind-merge`、`unplugin-vue-components` 已在；react/react-dom 19 是 Excalidraw 所需，与本次无关。

## 三、目标架构

```text
views/*（调用方，零改动）
  └─ App* 适配层（components/common/，对外 API 不变）
       ├─ 策略 A 组件内部 → ant-design-vue（a-input / a-select / a-modal …）
       │     └─ ConfigProvider（prefixCls="kb-ant" + theme=语雀 token 桥接）
       │           └─ a-app（message/modal 经 App.useApp() 取，继承前缀与主题）
       └─ 策略 B 组件内部 → 维持 Tailwind + --kb-* token（不动）
Tailwind 4：布局、页面级样式、状态类照旧（只管自建层，不与 .kb-ant-* 纠缠）
```

三条主线原则：

1. **适配层保 API**：策略 A 每个组件对外 props/slots/emits/expose 与迁移前逐一等价（验收项），调用方模板不改一行；antd 只出现在适配层内部与 `App.vue`。
2. **token 桥接**：antd 的颜色/圆角/高度全部来自 `--kb-*`（运行时 getComputedStyle 读取），禁止在适配层写死色值；`useThemeMode.isDark` 变化时整体重建。
3. **类名隔离**：antd-vue 一律 `kb-ant-*` 前缀；本项目 CSS（含 style.css）**永不出现 `.ant-` 裸前缀选择器**（spike 里 grep 验证），Lake 的 `.ant-*` 静态 CSS 归编辑器专属。

- [ ] **Task 1.2 主题桥接（TDD）**

  Create `src/renderer/src/composables/ant-design-theme.ts`——把「token 读取」做成纯函数便于测试：

```ts
/**
 * 语雀 token → antd ThemeConfig 桥接。
 * 语义层 --kb-* 是 var() 引用，getComputedStyle 拿到的已是按 .dark 换档后的计算值，
 * 因此只需在 isDark 变化时整体重建一次，不需要监听每个变量。
 */
import { computed } from "vue"
import { theme as antdTheme } from "ant-design-vue"
import { useThemeMode } from "./useThemeMode"

/** TokenReader：键名（不含 --kb- 前缀）→ 值。生产实现读 :root 计算样式。 */
export type KbTokenReader = (name: string) => string

const readFromRoot: KbTokenReader = name =>
  getComputedStyle(document.documentElement).getPropertyValue(`--kb-${name}`).trim()

/** 纯函数：给定 token 读取器与明暗模式，产出 ConfigProvider 的 theme 配置。 */
export function buildAntdTheme(isDark: boolean, read: KbTokenReader) {
  return {
    algorithm: isDark ? antdTheme.darkAlgorithm : antdTheme.defaultAlgorithm,
    token: {
      colorPrimary: read("brand"),
      colorInfo: read("info"),
      colorSuccess: read("success"),
      colorWarning: read("warning"),
      colorError: read("error"),
      colorText: read("text"),
      colorTextSecondary: read("text-secondary"),
      colorTextTertiary: read("text-tertiary"),
      colorTextQuaternary: read("text-quaternary"),
      colorBorder: read("border-input"),
      colorBorderSecondary: read("border"),
      colorBgContainer: read("surface-bg"),
      colorBgElevated: read("surface-bg"),
      colorBgLayout: read("background-base"),
      borderRadius: 8,          // --kb-radius-md
      controlHeight: 32,        // --kb-control-height-md
      fontFamily: read("font-display"),
    },
  }
}

export function useAntdTheme() {
  const { isDark } = useThemeMode()
  // isDark 变化 → computed 重算 → 全部 token 用新模式的计算值重新读取
  const theme = computed(() => buildAntdTheme(isDark.value, readFromRoot))
  return { theme }
}
```

- [ ] **Task 2.1 AppInput → a-input**（canonical，首个迁移）

  对外 API 必须保持：`modelValue`/`change` 双事件、`autofocus`（继续输出 data-autofocus 供 AppDialog）、`type/placeholder/disabled`、attrs 透传（maxlength、name 落到 input）、expose `focus()/blur()/select()`、cn() class 合并（调用方 class 优先）。

```vue
<script setup lang="ts">
/**
 * 输入框组件（内部实现换底 ant-design-vue a-input，对外 API 与纯自建版完全一致）。
 * 视觉仍由 --kb-* token 驱动：antd 的默认底/描边/聚焦样式在下方 scoped CSS 归零，
 * 由本组件统一输出语雀紧凑输入框样式。
 */
import { computed, nextTick, onMounted, ref, useAttrs } from "vue"
import { Input as AInput } from "ant-design-vue"
import { cn } from "@/utils/cn"

defineOptions({ inheritAttrs: false })

type InputValue = string | number | null | undefined

const props = withDefaults(
  defineProps<{
    modelValue?: InputValue
    type?: string
    placeholder?: string
    disabled?: boolean
    autofocus?: boolean
  }>(),
  { modelValue: "", type: "text", placeholder: "", disabled: false, autofocus: false }
)

const emit = defineEmits<{
  "update:modelValue": [value: string]
  change: [value: string]
}>()

const attrs = useAttrs()
const inputRef = ref<InstanceType<typeof AInput> | null>(null)

const normalizedValue = computed(() =>
  props.modelValue === null || props.modelValue === undefined ? "" : String(props.modelValue)
)

const forwardedAttrs = computed(() =>
  Object.fromEntries(Object.entries(attrs).filter(([key]) => key !== "class"))
)

const inputClass = computed(() =>
  cn("kb-antd-input w-full h-9", String(attrs.class ?? ""))
)

const focusInput = async () => {
  if (!props.autofocus) return
  await nextTick()
  inputRef.value?.focus()
}

onMounted(() => {
  void focusInput()
})

defineExpose({
  focus: () => inputRef.value?.focus(),
  blur: () => inputRef.value?.blur(),
  select: () => inputRef.value?.select(),
})
</script>

<template>
  <AInput
    ref="inputRef"
    v-bind="forwardedAttrs"
    :value="normalizedValue"
    :type="type"
    :placeholder="placeholder"
    :disabled="disabled"
    :data-autofocus="autofocus ? '' : undefined"
    :class="inputClass"
    @update:value="v => emit('update:modelValue', v ?? '')"
    @change="(e: Event) => emit('change', (e.target as HTMLInputElement)?.value ?? '')"
  />
</template>

<style scoped>
/* 语雀紧凑输入框：浅灰底、10px 圆角、13px 字号，聚焦只描边不加光晕。
   scoped unlayered，特异性压过 antd cssinjs（unlayered），不依赖 !important。 */
.kb-antd-input.kb-ant-input {
  border: 1px solid var(--kb-border);
  border-radius: 10px;
  background: var(--kb-muted-bg);
  color: var(--kb-text);
  font-size: 13px;
  padding: 0 12px;
  box-shadow: none;
  transition: border-color var(--kb-transition-fast);
}
.kb-antd-input.kb-ant-input::placeholder {
  color: var(--kb-text-quaternary);
}
.kb-antd-input.kb-ant-input:focus {
  border-color: var(--kb-brand);
  box-shadow: none;
}
.kb-antd-input.kb-ant-input:disabled {
  background: var(--kb-grey-200);
  color: var(--kb-text-quaternary);
  cursor: not-allowed;
}
</style>
```

  注意点：a-input 的 value 事件是 `update:value`；a-input expose 的 `focus()` 存在于其 ref 上；**autofocus 的 data-autofocus 属性会落到 a-input 根元素**，AppDialog 的 `querySelector("[data-autofocus]")` 命中的是包裹元素而非 input 本体——若焦点未生效，在 adapter 里改为 `nextTick` 后直接 `inputRef.focus()`（已有此逻辑，确认时序即可）。

## 附录 A：Lake antd.css 作用域化（仅 Task 1.3 决策门失败时启用）

思路：不动 yuque-editor-core submodule，在 `xiaoye` 侧对 `/yuque-assets/antd.css` 做**构建/服务期改写**，把所有 `.ant-*` 规则限定到编辑器容器 `.lake-scope` 下：

1. 改写规则：类/属性选择器一律加前缀 `.lake-scope `；`html/body/:root/*` 纯元素 reset 改写到 `.lake-scope` 自身（如 `body{...}` → `.lake-scope{...}`）；`@font-face`/`@keyframes` 原样保留；`@media` 内递归处理；`html.x`/`body.x` 复合选择器把首个元素替换为 `.lake-scope`。
2. 实现：`build/lake-antd-scope.ts` 用 postcss（已是 devDep）walk AST 完成；dev 端在 `build/shared.ts` 加一个 `configureServer` 前置中间件拦截 `/yuque-assets/antd.css` 响应改写后返回，build 端用 `generateBundle` 钩子重写 yuqueAssets 产出的同名产物。
3. 挂载点：`YuqueDocEditor.vue` 根容器加 `class="lake-scope"`。
4. 风险：编辑器若有 teleport 到 body 的 `.ant-*` 弹层，需把其容器类补进作用域或在内核侧改挂载（内核侧改动按 AGENTS.md 决策 3 走：实战需求驱动时直接在 yuque-editor 仓库做）；`style.css` 里现有 `.dark` 反覆盖规则的选择器需同步复查。
