# 当前知识库前端与语雀差距分析摘要

> 面向对象：老板 / PRD / 项目负责人
> 记录日期：2026-03-15

## 一句话结论

当前项目已经完成了知识库前端主流程、文档编辑器增强和画板能力的基线建设，和语雀的主要差距已经不再是“缺基础页面和基础功能”，而是**块模型统一、协作闭环、内容块生态与多场景一致性的系统化差距**。

## 一、当前项目已经做到什么程度

当前项目已经不是演示级知识库，而是一套可用的桌面端知识库前端，已经具备：

- 知识库列表、最近、收藏、回收站
- 工作区壳层与左侧文档树
- 文档树拖拽、右键菜单、展开状态记忆
- 文档编辑、自动保存、手动保存、离线重试、远端冲突检测
- 评论侧栏、版本历史、分享、导出、打印
- 较丰富的富文本内容能力
- Excalidraw 画板编辑
- 画板 AI 生成与素材库
- 成员与权限主流程

结论：

- 当前项目已经完成“知识库主流程闭环”
- 当前短板不在基础 CRUD，而在体验完成度和系统化程度

## 二、和语雀相比，差距主要在哪

### 1. 块模型还不够统一

当前编辑器已经具备提示块、折叠块、附件块、嵌入块、状态块、双栏等能力，也已经出现块 hover、选中、插入反馈和拖拽手柄。

但与语雀相比，当前更像“在富文本编辑器上做增强”，还没有形成一套统一、稳定的块级交互骨架。

这是当前最大的差距，也是最优先要补的方向。

### 2. 内容块已经不少，但还没有形成闭环

当前项目已经有不少高频内容块，问题不在“有没有块”，而在：

- 编辑态、只读态、分享态、导出态是否一致
- 模板、Slash 命令、插入入口是否形成统一消费路径
- 页面组织能力是否足够成熟

这部分差距会直接影响“像语雀一样搭内容”的体验。

### 3. 协作外围已具备，但协作闭环还不完整

当前项目已经有评论侧栏、版本历史、分享、权限、自动保存和远端冲突检测。

但与语雀相比，还缺：

- 更稳定的评论锚点和文内定位
- 评论、版本、分享之间的统一协作语义
- 实时协作能力
- 更强的多人协作反馈

### 4. 产品完成度和一致性还有差距

当前项目已经可用，但仍存在：

- 编辑态、只读态、分享态、导出态一致性不足
- 快捷键、搜索、块菜单层级仍需继续打磨
- 视觉节奏和交互反馈更偏工程实现，不够成熟产品化

## 三、哪些地方不应再被误判为短板

以下内容不应再被当作当前阶段的主要问题：

- 不是“没有知识库主流程”
- 不是“没有文档树能力”
- 不是“没有编辑器能力”
- 不是“没有权限、分享、版本、评论基础能力”
- 不是“没有特色能力”，因为画板已形成明显差异化

也就是说，当前项目已经跨过“从 0 到 1”的阶段，处在“从可用走向成熟”的阶段。

## 四、建议优先级

### P0：统一块模型

目标：

- 让块成为一级交互对象
- 统一高频块的 hover、选中、拖拽、插入和块菜单

### P1：补内容块闭环

目标：

- 把已有内容块打通编辑、阅读、分享、导出链路
- 提升模板、Slash 命令和页面组织能力

### P2：补协作闭环

目标：

- 强化评论锚点
- 打通评论、版本、分享语义
- 评估并推进实时协作

### P3：补一致性与细节完成度

目标：

- 收敛多场景体验
- 统一工具栏、块菜单、搜索、反馈等细节

## 五、最终判断

如果从产品阶段判断：

- 当前项目已经具备完整的知识库前端基线
- 和语雀的差距主要不在“有没有”，而在“是否系统化、协作化、成熟化”
- 后续重点不应继续按页面补功能，而应围绕块模型、协作闭环和一致性做系统性推进

这也是当前项目从“高质量业务实现”走向“成熟知识产品体验”的关键阶段。
