# 当前知识库前端追平语雀分阶段实施计划

> 记录日期：2026-03-15
> 适用范围：桌面端知识库工作台、文档编辑器、阅读/分享/导出链路

## 1. 文档目标

本文用于把《当前知识库前端与语雀差距分析》落到可执行层，明确：

- 当前阶段应该先做什么
- 每个阶段解决什么问题
- 每个阶段涉及哪些模块
- 每个阶段如何验收

本文是实施计划，不替代具体需求单与设计稿，但可作为后续排期和拆任务的基准文档。

## 2. 当前阶段判断

当前项目已完成知识库前端主流程、富文本编辑器增强、画板能力、权限与外围流程接入。现阶段与语雀的核心差距主要集中在以下四类：

- 块模型统一不足
- 内容块生态尚未闭环
- 协作闭环不足
- 多场景一致性与细节完成度不足

因此，后续实施不再以“继续补主流程页面”为主，而应以“系统化体验建设”为主。

## 3. 实施原则

### 3.1 先统一骨架，再补丰富能力

优先统一块交互骨架，而不是继续零散增加内容块。否则新增能力会继续放大不一致。

### 3.2 先补高频闭环，再补高级协作

先把编辑、只读、分享、导出等高频链路收敛，再推进实时协作，避免体验层继续分裂。

### 3.3 保持现有存储兼容性

实施过程中应继续兼容当前 Markdown / HTML 文档存储结构，不以“彻底重写编辑器协议”为前提。

### 3.4 固定桌面端范围

当前追平目标默认仅面向桌面端知识库工作台，不纳入移动端专属交互重构。

## 4. 分阶段路线图

## P0：统一块模型基础

### 目标

把当前“局部具备块能力”的编辑器，推进为“高频内容块具备统一交互骨架”的编辑器。

### 主要要解决的问题

- 块 hover、选中、插入反馈不够统一
- 不同块的交互骨架不一致
- 块移动、复制、删除、插入等行为缺少统一心智
- 当前更像富文本增强，而不是稳定块编辑器

### 重点实施项

#### 1. 抽象统一块容器能力

统一以下能力：

- 左侧操作区
- hover 态
- 选中态
- 插入位置反馈
- 拖拽入口
- 更多菜单入口

#### 2. 先覆盖高频块

优先统一以下节点：

- 图片
- 表格
- 引用
- 分割线
- 代码块
- 提示块
- 折叠块

#### 3. 统一块菜单动作

高频块统一支持：

- 上移 / 下移
- 复制块
- 删除块
- 插入同级块

### 涉及模块

- `src/components/editor/RichTextEditor.vue`
- `src/components/editor/extensions/*`
- 富文本相关块扩展与渲染逻辑

### 本阶段不做

- 实时协作
- 大量新增内容块
- 移动端适配
- 重写底层存储协议

### 验收标准

- 高频块具备统一 hover、选中、插入和菜单反馈
- 用户能明显感知“块”已成为一级交互对象
- 新交互不破坏现有 Markdown / HTML 兼容性

## P1：补内容块生态闭环

### 目标

从“内容块可插入”升级到“内容块在编辑、阅读、分享、导出中稳定闭环”。

### 主要要解决的问题

- 块存在但消费链路不够统一
- 只读、分享、导出场景下的块渲染一致性不足
- 模板、Slash 命令与内容块未形成成熟消费路径
- 页面组织能力不够强

### 重点实施项

#### 1. 补齐高频内容块闭环

优先围绕以下块做完整闭环：

- 提示块 / Callout
- 折叠块
- 附件块
- 嵌入块
- 状态块
- 双栏 / 分栏布局

每类内容块至少要覆盖：

- 编辑态
- 只读态
- 分享态
- 导出链路

#### 2. 强化 Slash 命令与插入入口

- 统一 Slash 命令分组与命名
- 统一块插入入口和反馈
- 缩短高频内容块的插入路径

#### 3. 强化模板与内容复用

- 让模板不只是入口，而是可支撑块复用的消费路径
- 提升常用结构模板的落地效率

### 涉及模块

- `src/components/editor/RichTextEditor.vue`
- `src/utils/knowledge-markdown.ts`
- 阅读渲染、分享渲染、导出渲染相关工具与组件

### 本阶段不做

- 实时协作正式接入
- 深度协作协议改造

### 验收标准

- 高优先级内容块在编辑、阅读、分享、导出中具备一致渲染
- Slash 命令成为主要内容块插入入口之一
- 文档页面不再主要依赖纯文本 + 图片 + 表格组合

## P2：补协作闭环

### 目标

从“有评论、有版本”升级为“围绕内容协作”的文档系统。

### 主要要解决的问题

- 评论当前仍偏侧栏讨论
- 评论锚点不够稳定
- 评论、版本、分享语义尚未打通
- 实时协作仍停留在预留层

### 重点实施项

#### 1. 强化评论锚点

- 建立评论与块 / 选区的稳定映射
- 提升评论定位、跳转、状态反馈能力
- 明确评论在只读与编辑态下的交互语义

#### 2. 打通评论、版本、分享

- 统一讨论、版本、分享之间的协作语义
- 减少这些能力之间的割裂感

#### 3. 评估并推进实时协作

- 基于现有预留状态评估接入路径
- 明确多人在线、冲突处理、在线状态展示边界
- 按资源情况推进实时协作最小闭环

### 涉及模块

- `src/views/knowledge/KnowledgeDocEditorView.vue`
- `src/utils/comment-anchor.ts`
- 评论、版本、分享相关 service / 组件
- 后续协作相关 composable / provider

### 本阶段不做

- 追求语雀级全量多人协同能力
- 重写整个后端协作协议

### 验收标准

- 评论不再只是侧栏信息流，而能稳定映射到文档内容
- 评论、版本、分享在用户认知上更统一
- 协作语义不再彼此割裂

## P3：补一致性与细节完成度

### 目标

把整体体验从“功能丰富”推进到“成熟稳定、细节统一”。

### 主要要解决的问题

- 编辑态、只读态、分享态、导出态存在差异感
- 工具栏、块菜单、辅助面板层级关系还不够清晰
- 快捷键、搜索、反馈等高频交互还可继续打磨

### 重点实施项

#### 1. 收敛多场景体验

统一以下场景：

- 编辑态
- 只读态
- 分享态
- 导出态

#### 2. 统一反馈体系

- 收敛保存反馈、错误反馈、块反馈、菜单反馈
- 统一交互层级与视觉节奏

#### 3. 优化高频操作路径

- 快捷键
- 搜索体验
- 模板消费体验
- 块菜单与工具栏切换逻辑

### 涉及模块

- 文档页壳层
- 编辑器工具栏、气泡菜单、块菜单
- 分享与导出链路
- 搜索、信息面板与辅助交互组件

### 本阶段不做

- 移动端专属重构
- 语雀全部外围产品能力复刻

### 验收标准

- 用户对多场景不一致的感知明显下降
- 高频操作路径更短、反馈更明确
- 产品整体完成度明显提升

## 5. 画板能力的实施定位

当前画板能力已形成项目特色，和语雀并非完全同一对标方向，因此建议：

- 继续维护画板作为独立优势能力
- 不把画板纳入“追平语雀文档编辑”的核心短板
- 优先保证画板与知识库工作台、权限、保存、AI 流程的一致性
- 文档编辑追平语雀的路线图，不应被画板需求打散主优先级

## 6. 排期建议

如果按推进顺序建议：

1. 先做 P0，统一块模型基础
2. 再做 P1，形成内容块闭环
3. 再做 P2，补协作闭环
4. 最后做 P3，统一一致性与细节完成度

原因：

- 如果块骨架不统一，后续新增块和协作锚点都会持续放大不一致
- 如果阅读 / 分享 / 导出链路不先收敛，协作能力落地后体验仍然会割裂
- 细节打磨应放在核心交互体系基本稳定之后

## 7. 风险与依赖

### 7.1 主要风险

- 当前编辑器仍基于富文本编辑器演进，统一块模型会涉及多类节点行为重构
- 一旦新增更多内容块，只读、分享、导出一致性风险会快速扩大
- 协作闭环会同时影响评论、版本、分享、权限与后端语义，不适合零散推进

### 7.2 关键依赖

- 持续保持 Markdown / HTML 兼容性
- 编辑态与只读态尽量复用同一套块渲染语义
- 每个阶段开始前都要先定义清晰范围与验收边界

## 8. 最终结论

当前项目后续追平语雀的正确路径，不是继续补零散页面，而是：

- 先统一块模型
- 再补内容块闭环
- 再补协作闭环
- 最后补多场景一致性与细节完成度

只要这个顺序不被打乱，当前项目就能从“高质量知识库前端实现”逐步演进为“成熟的知识产品体验”。
