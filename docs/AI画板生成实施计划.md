# AI 画板生成实施计划

## 背景与目标

当前项目已经把 Excalidraw 画板作为知识库体系内的一等内容类型接入，支持创建、编辑、分享与保存。下一步目标是在不修改 Excalidraw 原生保存格式的前提下，新增“AI 生成画板”入口，让用户可以通过自然语言生成流程图或结构化白板内容，并将结果以可编辑 scene 的形式注入当前画板。

本次实现遵循两个原则：

- AI 只负责生成草稿，不直接写入数据库。
- board 继续保存原生 Excalidraw scene，后续扩展不依赖自定义保存格式。

## 本轮边界

本轮交付范围：

- 后端新增 board AI 生成接口。
- 前端画板页新增 `AI 生成` 入口与生成侧板。
- 支持两类生成：
  - 流程图：自然语言 -> Mermaid -> Excalidraw elements
  - 白板卡片：自然语言 -> 受控 DSL -> Excalidraw elements
- 支持先生成草稿摘要，再选择替换当前画板或追加到右侧。

本轮明确不做：

- 图片生成与图片插入
- 局部智能改图
- 多轮对话式画板编辑
- 协同生成
- board 文本 diff

补充约束：

- Excalidraw 素材库改为“用户全局复用”，不跟随单个画板保存。
- 用户自定义素材不写入 `documents.content`，避免把 scene 与素材库大对象混存。
- 图片型素材不再塞进 `board_libraries.items`，改为独立资源表 + OSS 引用；`board_libraries.items` 只保留轻量 `libraryItems` 结构。

## 接口契约

### 后端接口

- `POST /api/knowledge/documents/:id/board-ai/generate`

请求体：

```json
{
  "prompt": "帮我画一个知识库文档审批流程",
  "mode": "auto"
}
```

请求字段：

- `prompt: string`
- `mode: "auto" | "flowchart" | "whiteboard"`

响应体：

```json
{
  "kind": "flowchart",
  "summary": "生成了一个审批流程草稿",
  "warnings": ["节点较多，建议插入后手动微调布局。"],
  "mermaid": "flowchart LR\n  A[发起申请] --> B[负责人审批]"
}
```

或：

```json
{
  "kind": "whiteboard",
  "summary": "生成了一个需求梳理白板草稿",
  "warnings": [],
  "boardDsl": {
    "nodes": [
      { "id": "n1", "type": "title", "text": "知识库 AI 方案" },
      { "id": "n2", "type": "card", "text": "问题梳理", "group": "现状" }
    ],
    "connectors": [
      { "id": "c1", "fromNodeId": "n2", "toNodeId": "n3", "label": "影响" }
    ]
  }
}
```

权限规则：

- 仅登录用户可用
- 需要对目标文档有 `read` 权限
- 接口只生成草稿，不直接修改文档

环境变量：

- `AI_API_KEY`
- `AI_API_BASE_URL`
- `AI_MODEL`
- `AI_TIMEOUT_MS`

## 前端改造点

- 新增 board AI 服务层，封装生成接口调用。
- 新增 AI 结果类型与 DSL 类型。
- 新增 scene 转换工具：
  - Mermaid -> Excalidraw
  - Whiteboard DSL -> Excalidraw
  - 追加到右侧的 scene 合并
- 在画板编辑页增加 `AI 生成` 按钮。
- 在画板编辑页接入 Excalidraw library 持久化：
  - 首次打开时加载当前用户全局素材库
  - 监听素材库变化并防抖保存
  - 通过 `initialData.libraryItems` 和 `updateLibrary()` 回填素材
  - 图片素材通过独立资源接口上传到阿里云 OSS，并在加载时按 `fileId -> URL` 重建 Excalidraw 文件缓存
- 增加右侧 AI 生成侧板，包含：
  - 自然语言输入
  - 模式切换
  - 生成按钮
  - 系统提示词展示
  - 摘要与警告
  - 替换当前画板 / 追加到右侧 / 重新生成

## 后端改造点

- 新增 `board-ai` 模块并注册到应用。
- 新增 `board-library` 模块，提供用户级素材库读写接口。
- 新增 `board_library_assets` 表与图片素材上传接口，资源元数据独立存储，文件实体走阿里云 OSS。
- 新增 DTO、Controller、Service。
- 服务端通过 OpenAI 兼容 HTTP 调用大模型，优先适配 DeepSeek。
- `auto` 模式先分类，再按流程图或白板卡片 prompt 生成。
- 输出统一为可解析 JSON，流程图返回 Mermaid，白板返回受控 DSL。
- 错误处理统一转换为用户可读提示，不透传底层模型异常。

## 风险与回退

- 模型输出不稳定时，优先保证接口返回结构稳定，再提示用户重试。
- Mermaid 转换失败时，不修改当前画板，只显示错误信息。
- 白板 DSL 若出现非法节点或断链，前端在转换前做过滤和兜底布局。
- 素材库当前拆为两层：轻量 `libraryItems` JSON + 独立图片资产表。后续如果还要承载更重的媒体资源，再继续拆缩略图、原图、权限和清理策略。
- 若 AI 服务不可用，画板原有创建、编辑、保存、分享链路不受影响。

## 测试清单

- 前端 `pnpm build`
- 后端 `pnpm build`
- 手工验证：
  - 画板页可打开 AI 生成面板
  - 流程图可生成、插入
  - 白板卡片可生成、插入
  - 替换当前画板后可保存并刷新恢复
  - 追加到右侧不会覆盖原内容
  - 同一用户在不同画板中共享同一套素材库
  - 刷新页面后自定义素材仍可恢复
  - 图片型素材上传到 OSS 后可被素材库重新加载
  - 失败时当前画板不被污染
  - 分享页继续只读显示 board，不出现 AI 入口
