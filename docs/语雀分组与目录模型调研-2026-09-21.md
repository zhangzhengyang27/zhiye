# 语雀「分组与目录」模型调研 — 2026-09-21

> **文档状态**：✅ 调研完成，批次 A/B 已实施并验证；**批次 C 已按用户纠正于同日回退**
> **起因**：用户指出「语雀中的知识库是没有目录的概念的，有的是分组」，要求调研后对齐。
> **用户决策修订（2026-09-21 截图纠正）**：分组功能指的是**第二栏文档树里的容器节点**（批次 A/B），**不是第一栏知识库列表的分组**。基于语雀源码 Stack 概念自行扩建的批次 C（侧栏知识库分组：模型/迁移/API/侧栏 UI）已整体回退——数据库表/列/迁移记录已删，代码已恢复原状。侧栏知识库分组（Stack）按产品决策**不做**，后续不要再立项。
> **结论先行**：语雀知识库的文档树里，容器节点叫**「分组」**，不存在「目录/文件夹」这种节点；「目录」在语雀只指**整棵树这个实体**（目录 tab、目录管理、移出目录、按目录顺序）。我们已把树内容器从「目录/文件夹」改名「分组」，并补齐语雀的**文档嵌套文档**（分组 > 文档 > 文档）。

## 一、语雀真实模型（证据）

### 1.1 层级全景

```text
团队 group（/dashboard/groups，扁平非容器，易与「分组」混淆，勿用）
  └─ 知识库分组 Stack / Bookstacks（一层容器，装知识库；默认分组不可删；
  │    删除分组后组内知识库迁入默认分组；上移分组/下移分组排序；移动到分组）
  └─ 知识库 book（类型：文档库/话题库/资源库/图片库/文件库…；知识库不套知识库）
       └─ 目录 ToC（整棵文档树的实体名：目录 tab / 目录管理 / 目录排序 / 按目录顺序）
            ├─ 分组节点（容器，可多级嵌套；「+」→「新建分组」创建）
            ├─ 文档节点（归入分组后才可层级嵌套：分组 > 文档 > 文档，最多 3 级）
            └─ 不在目录中的文档 → 展示在「全部文档」，可经「文档管理」添加到目录
       └─ 置顶 Pin（绑定目录，有数量上限；移出目录会同时取消置顶）
       └─ 排序：按目录顺序（默认）/ 创建时间 / 更新时间 / 标题
       └─ 首页风格：卡片视图 / 目录视图 / 专栏视图 / 自定义首页
```

### 1.3 用词纪律（改名的边界，最重要的一节）

语雀同一界面混用两个词，**各有严格分工**，改名必须精确到词而不是全局替换：

| 词 | 语雀指什么 | 我们照做吗 |
| --- | --- | --- |
| **分组** | ① 目录树里的**容器节点**；② 侧边栏**知识库分组**（Stack） | ✅ 本次核心 |
| **目录** | 整棵文档树这个**实体/视图**：目录 tab、目录树、目录列、目录管理、目录历史、移出目录、添加到目录、按目录顺序、目录视图（编辑器） | ✅ 全部保留现状 |
| **大纲** | 文档内标题层级（编辑器右侧） | ✅ 保留 |
| **文件夹** | 文件库/资源库里的上传文件夹 | ✅ 不借用此词 |
| **根目录** | 树根（移动/新建弹层的选项） | ✅ 保留（不改「根分组」） |
| **所属目录** | 新建文档弹层字段（指向目录树中的位置） | ✅ 保留（此前批次按真机对齐过，且 verify-t6 契约依赖） |
