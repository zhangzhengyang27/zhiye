## 决策 1：产品定位 = 复刻底座 + AI 差异化产品

**定位声明**：以语雀桌面端 1:1 复刻为底座，叠加自有 AI 能力（AI 写作、AI 画板生成），目标是**发布给真实用户使用的产品**，而非自用工具或纯学习项目。

派生影响（此前可容忍的事项升级为硬要求）：

- 交付链路：electron-builder 打包 + 干净机器安装验证必须走通（当前从未验证过）
- 数据出口：文档导出能力是数据信任底线，不可长期缺失
- 质量网：冒烟 + 人工验证之外需补自动化防线（见决策 4）
- 立项准入：新功能需回答三问——语雀有没有？用户频率多高？与 AI 差异化的关系？（Drive 网盘做了又删的教训）

## 决策 2：下一阶段主攻 = 编辑器刚需追平（P-C2 实时协同延后）

未来 2–4 周主攻编辑器高频刚需，P-C2（Yjs 文档级合并）移出当前队列、保留在需求池。排序依据：单人写作频率远高于多人实时协同，且 P-C2 工程量 1–2 周起步。

### 验收标准

- 工具栏可插入表格/代码块，编辑态与只读/分享/分享页渲染一致
- 编辑器内可搜索并高亮、逐个跳转、替换
- 任一文档可导出 Markdown 与 HTML，内容与编辑器渲染一致
- typecheck / lint / build:web / 冒烟全绿 + GUI 对照验收

## 附：yuque-editor 内核实战优化清单（决策 3 的落地记录）

编辑器刚需追平实施中发现的内核侧问题，按「内核在实战中优化」的原则在此登记：

1. **✅ 已修复（2026-09-11）**：`vue.ts` expose 漏列 `execCommand`——`YuqueEditorRef` 接口声明了该方法但组件 expose 未透传，宿主经 ref 调用时运行时报 not a function。已补透传并重新构建内核。
2. **✅ 已修复（2026-09-11，编辑器查找替换批次）**：
   - doc.umd.js search 插件 `replaceText` 命令缺 `commitJob`——替换停留在未提交事务，后续无编辑操作时保存/刷新丢改动。以构建期补丁修复（`packages/core/scripts/patch-doc-umd.cjs`，幂等、目标串唯一性校验、上游变更时显式报错）
   - 替换命令不触发 `contentchange` 事件——宿主 v-model 停留旧值。封装层（editor.ts）对 replaceText/replaceAll 透传后补发内容同步
3. **⏳ 待内核排查**：codeblock 卡片 CodeMirror 编辑区不渲染——`window.CodeMirror` 已加载、卡片可激活（`codeblock-menu` 出现），但卡片内 CodeMirror 实例不挂载，代码块无法输入内容。复现：文档页插入代码块 → 点击卡片。内核菜单插入的卡片同样表现，属既有链路缺陷，非宿主引入。
4. **⏳ 待内核补充**：codeblock 主题枚举/暗色适配 API 未暴露——宿主插入代码块需自构 cardValue（`{ mode, theme }`），暗色主题枚举值（内核内部变量）拿不到，当前固定 `Github Light`，dark 模式下新建卡片为亮色主题。
5. **⏳ 待内核确认**：空代码块卡片（cardValue 为 null）在 markdown 序列化时被丢弃——宿主插入必须携带基础 cardValue 字段才能持久化，内核宜在 insertCard 命令层对 null value 兜底为标准 value。
6. **⏳ 待内核完善（search 边界）**：a) 替换后面板重定位选区偶发 Range offset 未捕获异常（不影响替换持久化）；b) "全部替换"不触发 change 驱动的自动保存调度（⌘S 保存已由宿主侧保存前同步兜底，自动保存路径待内核事件层完善）。
