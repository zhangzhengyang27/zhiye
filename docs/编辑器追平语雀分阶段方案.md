# 编辑器追平语雀分阶段方案

> 记录日期：2026-03-15
> 适用范围：桌面端知识库工作台中的文档编辑器

## 1. 背景与目标

当前仓库中的编辑器已经完成了知识库场景下的基础闭环，具备富文本编辑、代码块增强、Mermaid 渲染、目录、搜索、评论侧栏、分享、历史版本等能力，已经不是演示级编辑器。

但如果目标是“追平语雀的文档编辑体验”，当前差距已经不再是单个按钮或单项功能，而是以下四类系统性能力：

- 统一块模型
- 丰富内容块
- 协作闭环
- 编辑细节与跨场景一致性

本方案的目标不是复刻语雀全部能力，而是在当前仓库约束下，形成一份可持续执行的路线图，明确：

- 当前编辑器与语雀的主要差距在哪里
- 哪些差距优先级最高
- 后续应该按什么顺序推进
- 每个阶段做什么、不做什么、如何验收

## 2. 当前能力盘点

### 2.1 已具备的编辑能力

- 基础富文本能力：
  - 标题、段落、列表、引用、分割线
  - 加粗、斜体、删除线、下划线、链接
  - 文本颜色、背景高亮、字号、对齐
- 结构化内容：
  - 表格
  - 图片上传与粘贴
  - 代码块
- 编辑辅助：
  - Slash 命令
  - 目录与大纲预览
  - 文档内搜索
  - Starter Templates
- 协作外围：
  - 评论侧栏
  - 分享
  - 历史版本
  - 自动保存

### 2.2 已具备的代码块能力

- 自定义代码块头部
- 标题、语言、主题、行号、自动换行、折叠
- 复制代码、运行占位、更多菜单
- 代码格式化
- Mermaid 编辑态预览
- Mermaid 在只读页、分享页、导出 HTML / PDF / Word 中渲染成图

### 2.3 当前默认判断

- 当前最优先缺口：统一块模型
- 当前最接近语雀的能力：代码块体系
- 当前最大产品差距：块模型、丰富内容块、协作锚点、编辑一致性
- 当前主场景：桌面端知识库工作台
- 当前不纳入范围：移动端专属编辑、完整语雀全量能力复刻

## 4. 分阶段路线图

### P0：统一块模型基础

目标：

- 把当前“以富文本编辑器为主、局部块能力增强”的状态，升级为“统一块级交互骨架”
- 把代码块中已经成熟的块交互模式，推广到其他高频内容块

重点改造：

- 抽象统一块容器能力：
  - 左侧操作区
  - hover 态
  - 选中态
  - 插入位置反馈
  - 拖拽入口
  - 更多菜单入口
- 统一高频块的交互壳：
  - 图片
  - 表格
  - 引用
  - 分割线
  - 代码块
- 统一块级菜单动作：
  - 上移 / 下移
  - 复制块
  - 删除块
  - 插入同级块

本阶段不做：

- 新增大量新内容块
- 实时协作
- 移动端适配

验收标准：

- 读者能明显感知“块”已经成为一级交互对象
- 高频内容块具备统一的 hover、选中、菜单和拖拽反馈
- 新增块级交互不破坏当前 Markdown / HTML 存储结构

### P1：补高频内容块

目标：

- 从“能写文档”升级到“能像搭积木一样搭知识库内容”

重点改造：

- 新增高频内容块：
  - 提示块 / Callout
  - 折叠块
  - 附件块
  - 嵌入块
  - 分栏
  - 任务 / 状态块
- 把新块统一接入：
  - Slash 命令
  - 块级插入入口
  - 只读渲染链
  - 导出链

本阶段不做：

- 实时协同
- 评论锚点深度改造

验收标准：

- 高优先级内容块具备编辑、只读、分享、导出的一致渲染
- Slash 命令成为主要插入入口之一
- 文档内容不再主要依赖纯文本 + 图片 + 表格组合

### P2：补协作闭环

目标：

- 从“单人编辑器”升级为“协作文档系统”

重点改造：

- 评论锚点与内容块/选区绑定
- 评论、版本、分享、只读语义统一
- 为实时协作接入保留接口与状态设计
- 视资源情况评估并推进实时协同接入

本阶段不做：

- 追求语雀级全量协同能力
- 重做后端接口协议

验收标准：

- 评论不再只是侧栏信息流，而能和文档具体内容建立稳定映射
- 分享与只读模式下的协作语义清晰一致
- 版本、评论、分享之间不再彼此割裂

### P3：补编辑细节与一致性

目标：

- 把产品完成度和细节稳定性拉齐

重点改造：

- 统一编辑态、只读态、分享态、导出态
- 统一固定工具栏、气泡菜单、块菜单的视觉与交互反馈
- 优化快捷键、搜索体验、模板消费体验
- 继续收敛块级样式和内容渲染细节

本阶段不做：

- 移动端专属编辑体验
- 语雀全部外围产品功能

验收标准：

- 用户对“编辑里长这样，分享/导出又变样”的反馈明显减少
- 高概率高频操作具备明确反馈和稳定路径
- 工具栏、气泡菜单、块菜单之间的层级关系更清晰

## 5. 每阶段范围 / 非范围

### 固定范围

- 桌面端知识库工作台
- 当前仓库的富文本编辑器与其只读 / 分享 / 导出链路
- 与知识库文档编辑直接相关的内容块、交互和协作能力

### 固定非范围

- 移动端专属编辑体验
- 完整语雀产品能力复刻
- 与知识库文档编辑无直接关系的外围产品系统重做
- 为追平体验而重写整套后端协议

## 6. 验收标准

本路线图的整体验收标准固定如下：

- 读者只看本文，就能明确知道当前差距、下一阶段重点、每阶段做什么与不做什么
- 高优先级差距不会被放到路线图末尾
- 后续每次进入实施阶段时，都能直接以本文作为范围边界与验收基线
- 本文仅在阶段边界、优先级调整或范围变化时更新，不按日常提交频繁改动

## 7. 风险与依赖

### 7.1 主要风险

- 当前编辑器底层仍以富文本编辑器为核心，块模型统一会涉及多类节点行为重构
- 只读、分享、导出链路已经开始统一，但一旦新增块种类，渲染一致性风险会扩大
- 协作闭环会同时牵动评论、版本、分享、权限和后端语义，不适合零散穿插推进

### 7.2 关键依赖

- 继续保持 Markdown / HTML 文档的兼容性
- 编辑态与只读态尽量复用同一套块渲染语义
- 每个新阶段都要先定义清晰的验收边界，再进入实现
