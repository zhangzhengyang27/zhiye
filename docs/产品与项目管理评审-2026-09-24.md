## 三、产品视角评估

### 3.1 定位成立，但「差异化」目前只是一个按钮，不是一个理由

已落地的 AI 能力（AI 写作面板的总结/大纲/续写/润色 + 画板生成）本质是 DeepSeek 通用封装，竞品（语雀 AI、Notion AI 等）全都有，**构不成迁移理由**。用户不会因为「长得像语雀、AI 也差不多」而切换。

但项目手里握有一个尚未变成卖点的真正差异化资产：**数据自有**。自建后端 + NAS MinIO + 本地桌面端这套架构，天然是「私有部署 / 数据在自己手里」的语雀替代品。对担心数据被平台锁定的个人和小团队，这比通用 AI 更有吸引力。

**建议**：下一轮定位决策明确三件事——目标用户是谁（个人知识工作者？小团队？）；核心切换理由（数据自有 + AI 理解你的知识库？）；AI 差异化从「通用写作辅助」收敛到「知识库原生 AI」（基于双向链接与全库内容的问答/自动整理），这才是复刻底座之上的护城河。

### 3.2 商业化合规是最大战略风险，需正视

对商业产品公开分发而言，**「1:1 复刻语雀 UI」+ Lake 编辑器内核的代码来源 + `yuque-source/`（语雀桌面端参考源码）的存在**，构成潜在知识产权风险。作为学习/自用没有问题；一旦以「知叶」名义公开发布并面向真实用户（尤其收费），界面著作权/装潢风险与内核代码来源清洁性都可能构成实质威胁——该风险不因工程质量高而消失。

**建议**（作为公开发布的前置关卡立项，不走一步看一步）：

1. 确认 yuque-editor-core 中不存在从语雀编译产物提取的专有代码；`yuque-source/` 严格保持参考用途、不进发布产物；
2. 评估 UI 逐渐建立自有视觉身份的路径（当前色彩 token 与语雀同值，长期可品牌化偏离）；
3. 商标 42 类查重尽快完成。

### 3.3 发布阻断项本质是产品决策，不只是工程任务

| 阻断项 | 背后的产品决策 |
| --- | --- |
| 仅 mac arm64 | 目标用户在国内则 Windows 是大头，不做等于放弃主要市场；该决定影响 updater/签名/测试矩阵，**必须现在定** |
| 后端地址写死 localhost:3200 | 桌面产品分发后后端在哪（自建云 vs 用户自托管）？决定运营形态，是商业模式问题 |
| 代码块 CodeMirror 不挂载 | 代码块是知识管理高频刚需，任何对外版本前必须解决或明确降级 |
| 版本号 0.0.0 | 公测前建立版本方案（建议 0.1.0-beta 起）+ 自动更新通道，否则第一批用户永远停在有 bug 的版本 |

### 3.4 缺少「从真实用户身上学习」的回路

目前无崩溃上报、无使用统计、无反馈渠道、无 AI 用量成本核算（服务端 DeepSeek key 是项目方付费）。建议把「最小反馈闭环」（崩溃上报 + 一个反馈入口 + AI 配额）列为公测前交付物；公测规模控制在 5–10 个种子用户，先验证「周留存 + 文档写作频次」一个指标，再谈放量。

## 四、项目经理视角评估

### 4.1 【最紧急】两仓零远端备份

`zhiye` 与 `zhiye-server` 的 `git remote` 均为空，**全部代码只存在一台机器上**，而本项目 09-21 刚发生过工作区整体消失。同类事故再来一次，未必能再次救回。OSS 无异地冷备是同类风险。

**行动（合计约一小时，先于一切新功能）**：建私有远端并推送两仓；确认内核仓远端在位；Postgres 每日 `pg_dump` 定时任务；OSS 桶启动 mc mirror 冷备。

### 4.2 无 CI，质量防线全靠人的纪律

typecheck/lint/build/冒烟四件套完善但全靠本地手动。在「单人 + 多 AI 代理并行」模式下，没有 CI 意味着任何代理引入的回归都可能悄悄进主干。**建议最小化起步**：一条 CI 流水线（typecheck + lint + vitest + build:web，推送触发），冒烟后置到每日定时。不需要重，需要存在。

### 4.3 测试形态健康，单测欠账按计划收

Playwright 冒烟体系（含拖拽/回滚/双账号）是真实资产。但决策 4 规划的核心逻辑单测基本未落地：前端 2 个 spec、后端 7 个，对比计划清单（use-tree-drag 校验/回滚、分享密码与过期、成员权限）缺口明显。**建议不追覆盖率指标**，按原计划收口「钱路」纯逻辑即可——尤其权限解析与 share-crypto，这两处出 bug 是数据安全事故。

### 4.4 发布工程需要一张明确里程碑表

建议立项 **「0.1.0 私测版」里程碑**，收拢散落的阻断项：版本方案 + Apple 签名公证（Developer ID）+ electron-updater 更新源 + 后端地址可配置 + 干净机器安装验证（决策 1 的硬要求，至今从未完整走过）+ 平台范围决策落地。**该里程碑排在一切新功能（小记打磨、思维导图、数据表等 P3 项）之前**——冻结新产品线直到交付链路通，这是对「Drive 网盘做了又删」教训的制度化。

### 4.5 工程卫生三项小手术

1. 前端 scripts/ 约 50 个 tmp-*/probe-* 临时脚本：归档到隔离目录或删除，保留的验证脚本补用途注释；
2. 后端 docs/ 被 gitignore：部署/运行手册不入库是反模式（密钥不入库是对的，文档应入库）——调整 ignore 规则并补生产部署文档；
3. 数据库测试库残留（2026-09-24 实测 25 个：14 个 Smoke Workspace + 11 个视觉审计/探针类脚本残留）——已全部级联清理，现仅存种子「默认知识库」；`cleanup-smoke-data.mjs` 建议冒烟后例行运行。

### 4.6 安全预发布清单（公测前完成）

- 删除 `src/common/guards/jwt.strategy.ts:25` 的 `'change-me'` 弱默认回退（与 jwt-secret.util 缺失即抛错的严格设计不一致）；

### 4.7 值得保持的资产（不是客套，是要求）

以下纪律是项目最值钱的资产，应当保持并延伸到「交付」与「风险」域：决策文档带「效力/日期/冲突以本文为准」的权威级管理；「语雀有没有/频率多高/与 AI 关系」三问立项闸门；「实测优先于记忆」纪律（两次被截图纠偏后写入规范）；AGENTS.md 已知坑清单作为活的教训库；性能预算可断言化；明暗双主题验收纪律。
