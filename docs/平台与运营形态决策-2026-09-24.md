# 平台与运营形态决策（2026-09-24）

> 决策日期：2026-09-24
> 决策方式：用户对《产品与项目管理评审-2026-09-24.md》待决策项四问四答拍板
> 效力：本文为路线决策记录，与《产品定位与路线决策-2026-09-11.md》共同生效；**平台范围与后端运营形态域内**如与历史文档冲突，以本文为准

## 决策 A：桌面平台范围 = 仅 macOS

- 私测与正式版只打 mac，electron-builder 维持 dmg/arm64 现状不变。
- Windows/Linux 的打包（NSIS）、签名、自动更新、测试矩阵**全部移出范围**，不做预留设计。
- 影响：0.1.0 私测里程碑瘦身；「平台范围」不再是待决事项。

## 决策 B：后端运营形态 = 纯自托管

产品**不运营官方云端后端**；用户自备服务器/NAS 部署 zhiye-server（配套《生产部署》手册），桌面端连接自托管后端。

派生影响（硬要求）：

- **桌面端后端地址可配置升级为发布阻断级需求**：09-20 阻断项「地址写死 localhost:3200」的修复方向由「打包写死官方地址」改为「设置可配 + 首次启动引导配置」；
- 「数据自有」从隐性差异化卖点升级为**产品形态本身**，作为核心叙事；
- AI 通道（DeepSeek）、SMTP 发信、对象存储（S3/MinIO）均为自托管者自配项——成本模型从「官方代付 + 配额管控」变为「用户自付」，评审文档 3.4 节的「AI 配额」诉求相应弱化为自托管者的自保护配置；
- 《zhiye-server/docs/生产部署.md》从内部手册升格为**用户侧交付物**，需按「用户照着能跑通」标准打磨（docker-compose 一键起在列）。

## 决策 C：商业化合规专项 = 暂不立项

风险接受并登记在案（评审文档 3.2 节）：UI 复刻与内核来源的合规评估**不作为**当前发布前置关卡；商标 42 类查重仍建议择机完成（低成本高保障）。若未来转向公开商业化运营（含收费），本决策须重新评估。

## 对 0.1.0 私测里程碑的范围修订（评审行动清单 #3）

1. Apple 签名 + 公证（外部依赖：Developer ID 账号，$99/年）
2. 自动更新通道（electron-updater + 更新源）
3. **桌面端后端地址可配置 + 首次启动引导**（决策 B 派生，新增）
4. 干净机器安装验证
5. 代码块 CodeMirror 内核缺陷解决或明确降级（不变）
